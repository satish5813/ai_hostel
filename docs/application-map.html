The system

Who connects to what

People use one web app. Every rule (approval order, fees, who may act) is enforced in the database, so a screen can never skip a step. Devices and outside services plug in at the edges.

A hostel student's year

From joining to leaving

The path every student takes. The money steps follow the joining and renewal rules: deposits and registration are paid once, the hostel fee, mess fee and meter charge every year.

Fine-tuning

What to do before and after Wednesday

Ordered by what blocks going live. Open an item for the detail.

Before the server goes live

MustSMS and WhatsApp are not sentDeveloper + IT

The sender marks messages as sent without contacting any provider, so parents never get outing links and students never get reminders. Connect a provider (for example MSG91 or the university's gateway) and record failures instead of hiding them.

MustUniversity sign-inIT

The Keycloak address and app registration for the server. Without it the API will not start in production, by design. Demo logins stay off.

MustStart production from a clean databaseDeveloper

Build the server database from the migrations, not from this demo copy, so no demo students, deposits, tickets or health reports go live. Then load the real hostels, rooms, students, staff and duties through Data administration.

MustFees for 2026-27 and 2027-28Accounts

Confirm every room type's registration fee, hostel fee, both deposits, meter charge and mess fee. Enter the deposits students already paid as opening balances.

MustOnline paymentsAccounts + IT

Razorpay live keys and the webhook address on the server. Until then fees are recorded only as cash or bank receipts at the counter.

MustCode on GitHub and the server runnerYou + IT

Push the saved version to the private repository, protect the main branch, add the production approver, and install the runner on the server (scripts/deploy/SERVER-SETUP.md).

MustA tested restoreIT

The deploy takes a backup each time. Restore one once on a spare database to prove it works.

This week, alongside go-live

ShouldVacating screens (workflow N)Developer

The rules are in the database, but there are no screens. Deposit refunds require an approved vacate, so this is the next build.

ShouldFloor Managers for every floorHostel office

Girls Hostel 1 has no Floor Manager assigned, so its outings and room changes fall back to the Chief Manager. Assign duties for every hostel.

ShouldAutomatic tests for the newest modulesDeveloper

Room change, deposits, health records and the joining/renewal fees were tested by hand. Add them to the automatic checks so later changes cannot break them.

ShouldDiscipline screens (workflow M)Developer

Record, verify, punish and ratify. The executive dashboard already reads discipline data.
